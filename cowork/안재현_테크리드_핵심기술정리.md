## 🏗️ 2. 안재현 전담 백엔드 코어 4대 모듈 심층 해설

### ① `app/core/config.py` — Pydantic-Settings 기반 전역 환경설정
* **설계 목적**: API 키, DB 주소, 보안 비밀키 등 모든 민감정보를 코드에 하드코딩하지 않고 `.env` 파일에서 안전하게 로드하는 중앙화된 설정 관리자.
* **적용 패턴**: **싱글톤(Singleton) 패턴** (`settings = Settings()`)으로 프로젝트 어디서든 단일 인스턴스를 공유.
* **핵심 구현 디테일**:
  - `BaseSettings`와 `SettingsConfigDict(env_file=".env", extra="ignore")`를 사용하여 유연한 환경변수 파싱 지원.
  - 조명환 팀원의 AI 프록시를 위한 `AI_BASE_URL` 및 권태현 팀원의 관리자 조회를 위한 `ADMIN_API_KEY`까지 수용할 수 있도록 유연한 확장 구조 마련.
* **과제 제약 충족**: 코드베이스 내 민감정보 노출 0건 및 `.gitignore`를 통한 `.env` 유출 원천 차단.

---

### ② `app/core/database.py` — SQLAlchemy 연결 풀 및 의존성 주입 (DI)
* **설계 목적**: 신재은(User 모델)과 권태현(ChatLog 모델)이 공유할 데이터베이스 엔진과 세션을 안전하게 공급.
* **핵심 기술 선택 및 원리**:
  1. **`connect_args={"check_same_thread": False}`**:
     - *배경*: SQLite는 기본적으로 단일 스레드 커넥션만 허용합니다.
     - *이유*: FastAPI는 고성능 처리를 위해 요청마다 비동기 이벤트 루프와 별도 워커 스레드를 넘나듭니다. 이 옵션이 없으면 `"SQLite objects created in a thread can only be used in that same thread"` 오류로 서버가 다운되므로 필수 적용했습니다.
  2. **`yield get_db()` 제너레이터 & 의존성 주입**:
     - FastAPI의 `Depends(get_db)`를 통해 HTTP 요청 수신 시 DB 세션을 오픈하고, 처리가 끝나면 `finally: db.close()`가 100% 실행되도록 보장하여 **데이터베이스 커넥션 풀 고갈(누수)을 원천 방지**했습니다.

---

### ③ `app/core/logger.py` — 표준 로거 및 Request-ID 추적 미들웨어
* **설계 목적**: 과제 필수 요구사항(서버 로그에 `[요청 수신]` 등 필수 이벤트 기록)과 분산 트래픽 추적성을 충족.
* **핵심 구현 디테일**:
  1. **고유 Request-ID 부여**:
     - 모든 들어오는 요청에 `str(uuid.uuid4())[:8]` 고유 식별자를 부여하여 `request.state.req_id`에 저장하고, 응답 헤더(`X-Request-ID`)로 반환하여 클라이언트와 서버 간 1:1 트랜잭션 추적이 가능하도록 설계.
  2. **역방향 프록시(Cloudflare Tunnel) 환경의 실제 클라이언트 IP 추출**:
     - *문제*: 리버스 프록시나 터널 뒤에 서버가 있으면 `request.client.host`가 무조건 내부 루프백(`127.0.0.1`)으로 찍혀 실제 사용자 IP를 알 수 없음.
     - *해결*: 프록시가 헤더에 실어 보내는 `X-Forwarded-For`와 `X-Real-IP`를 우선 파싱하도록 구현하여, 외부 접속자의 실제 공인 IP를 완벽하게 로그에 기록:
       ```python
       forwarded_for = request.headers.get("x-forwarded-for")
       if forwarded_for:
           client_host = forwarded_for.split(",")[0].strip()
       ```
  3. **콘솔(stdout)과 파일(`server.log`) 듀얼 출력**:
     - `StreamHandler(sys.stdout)`와 `FileHandler("server.log", encoding="utf-8")`를 동시 등록하여, 터미널 화면뿐만 아니라 파일로도 로그가 영구 보존되도록 구현.

---

### ④ `app/main.py` — 애플리케이션 진입점 및 생명주기(Lifespan) 관리
* **최신 FastAPI Lifespan 패턴 적용**:
  - 기존의 deprecated된 `@app.on_event("startup")` 대신 최신 권장 표준인 `asynccontextmanager` 기반 `lifespan(app: FastAPI)` 컨텍스트 매니저를 도입.
  - 서버 시작 시 `User`와 `ChatLog` 모델을 명시적으로 사전 임포트한 뒤 `Base.metadata.create_all(bind=engine)`을 호출하여, **서버 최초 기동 시 SQLite 테이블이 자동으로 누락 없이 생성**되도록 초기화 파이프라인 완성.
* **3인 팀원 라우터 통합**:
  - 신재은: `/api/auth` (회원가입, 로그인, JWT 세션)
  - 조명환: `/api/chat` (AI 파이프라인, 실시간 질의응답)
  - 권태현: `/api/logs` (사용자 대화 로그, 관리자 로그) 및 HTML/Static 마운트

## 🌐 3. 배포 인프라 및 네트워크 최적화 (Cloudflare Tunnel)

### ① 왜 Cloudflare Tunnel(`run_tunnel.ps1`)인가?
* **과제 제약 충족**: 과제 필수 요구사항 제19항, 제75항은 *"평가 시점에 외부 네트워크에서 접속 가능한 서비스 URL이 제공되어야 한다"*고 명시합니다.
* **기존 방식 대비 장점**:
  - *포트포워딩/공유기 개방*: 로컬 공유기 설정 변경 및 홈 네트워크 보안 취약점 노출 위험.
  - *유료 클라우드(AWS/GCP)*: 배포 비용 발생 및 외부 API 키 노출 관리의 번거로움.
  - *Cloudflare Tunnel*: 인바운드 방화벽 포트를 일체 열지 않고, 내부에서 Cloudflare 엣지 네트워크로 암호화된 아웃바운드 터널을 연결하여 안전한 HTTPS 도메인을 무료로 즉시 발급.
* **자동화 UX**:
  - `cloudflared.exe` 자동 다운로드 및 실행.
  - 발급된 공인 URL을 정규식으로 감지하여 콘솔에 대형 강조 박스로 출력하고, **사용자의 기본 웹 브라우저를 해당 주소로 자동 팝업**.

### ② Windows 전용 트러블슈팅: 포트 8000 ➔ 8080 변경 이유
* Windows 운영체제(Hyper-V, WSL, WinNAT)는 특정 동적 포트 범위(예: 7952~8051)를 시스템 전용으로 예약하여 `[Errno 13] Permission denied`를 발생시킵니다.
* 안재현 테크리드는 이를 회피하기 위해 기본 포트를 **`8080`**으로 선제적 표준화하여 어떤 윈도우/맥 환경에서도 무결하게 서버가 실행되도록 조치했습니다.

### Q1. "팀장으로서 이번 프로젝트 아키텍처를 설계할 때 가장 중점을 둔 원칙은 무엇인가요?"

> *설정값은 `config.py`의 싱글톤 `settings`를 통해 환경 변수로 일원화했고, DB 세션은 `database.py`의 `Depends(get_db)`로 주입해 누수를 방지했습니다. 또한 로깅 미들웨어에서 공통 `Request-ID`를 부여해 어떤 팀원의 API에서 병목이나 에러가 발생해도 단 하나의 ID로 전 구간을 추적할 수 있도록 설계했습니다."*

---

### Q2. "로깅 미들웨어에서 `X-Forwarded-For` 헤더를 별도로 파싱한 이유는 무엇인가요?"
> **답변 가이드**:  
> *"과제 요구사항에 '실제 외부 네트워크 접근성'과 '요청 수신 로깅'이 있었습니다. Cloudflare Tunnel이나 리버스 프록시를 통과하면 백엔드 입장에서는 클라이언트 IP가 무조건 로컬 호스트인 `127.0.0.1`로 둔갑합니다.*  
> *따라서 프록시가 원래 클라이언트의 공인 IP를 담아 전달해 주는 `X-Forwarded-For` 및 `X-Real-IP` 헤더를 우선 추출하도록 구현하여, 외부에서 접속한 평가관님의 실제 IP가 서버 로그에 정확히 찍히도록 만들었습니다."*

---

### Q3. "외부 배포는 어떤 방식으로 이루어졌으며, 인프라의 안정성을 어떻게 보장했나요?"
> **답변 가이드**:  
> *"로컬 백엔드 서버에 **Cloudflare Quick Tunnel**을 결합한 하이브리드 배포 방식을 구축했습니다.*  
> *외부 침입 위험이 있는 포트포워딩 대신 안전한 아웃바운드 터널을 사용해 공인 HTTPS 도메인을 실시간 발급받았으며, 윈도우 환경의 OS 포트 예약 충돌 문제를 해결하기 위해 표준 포트를 8080으로 지정했습니다. 이 모든 과정을 `scripts/run_tunnel.ps1` 스크립트 1줄로 자동화하여 uvicorn 기동, 터널 연결, 브라우저 팝업까지 원클릭으로 구동되도록 인프라를 완성했습니다."*
